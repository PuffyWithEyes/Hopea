# Импорт музыки из сервисов

Открыть: меню плеера → **Bring Your Music Over… → Import Account…**.
Импорт читает личную коллекцию аккаунта: сохранённые песни, плейлисты и
альбомы. Это не обход всего каталога сервиса.

Кнопка **Import** становится доступна после ввода данных сессии или токена;
для VK также нужен положительный числовой ID профиля. Во время входа кнопка
заблокирована, а недостающие данные указаны под формой. Пустые ссылки и списки
тоже нельзя отправить. Ошибки запуска показываются отдельным окном, даже если
панель поиска закрыта.

После входа сначала читается коллекция, затем открывается **Choose Music to Import**.
Во время чтения доступна **Cancel**: она отменяет подготовку и останавливает загрузчик каталога.
Вверху окна выбора — горизонтальная лента **Albums and Playlists**. Галочка рядом
с названием выбирает всю коллекцию, **Open Tracks →** открывает её песни.
Переключатель **Import Cover Art** отключает загрузку и обновление обложек для всех платформ; существующие изображения сохраняются.
Все новые песни выбраны сразу; возможные дубликаты выключены и доступны через **Duplicates**.
Треки прокручиваются непрерывным списком без **Next / Previous**. Галочка
**Select all tracks** выбирает или снимает выбор во всём открытом списке, включая
строки вне экрана. При поиске **Select all matches** действует на все совпадения.
Выбор сохраняется при прокрутке, поиске и переходах между коллекциями. **All Songs**
возвращает общий список. Один трек,
встречающийся в нескольких коллекциях, выбирается и импортируется один раз.
В ленте показаны коллекции, которые вернул сервис. Одно лишь название альбома
в тегах песни не создаёт отдельную коллекцию.

**Import Selected** запускает фоновый импорт. Можно слушать музыку,
переходить между вкладками и закрывать главное окно: приложение удерживается до
завершения задания. Полный выход из приложения прекращает задание; готовые файлы
и история сохраняются. Кнопка **Import Progress** в главном заголовке открывает
счётчики только во время активного задания. После завершения кнопка
исчезает, а уведомление **View Result** открывает результат.
После запуска импорта **Close** закрывает окно прогресса и не отменяет импорт.
После выбора музыки появляется
красная **Stop Import**: она останавливает фоновые загрузчики, сохраняя уже
добавленные треки. После остановки, ошибки или завершения остаётся **Close**;
устаревшая строка чтения и полоса прогресса при ошибке скрываются.
При тайм-ауте ВК импортёр повторяет тот же запрос до трёх попыток и показывает
этап чтения. Если часть каталога уже прочитана, её можно выбрать для импорта;
неполный результат явно отмечается предупреждением.

Обложки берутся из метаданных сервисов, загружаются без cookies, проверяются и
сохраняются рядом с кешированными файлами как `*.cover.jpg`. Название альбома,
исполнитель альбома и номер трека записываются в аудио, когда сервис их отдаёт.
Недоступная обложка не мешает импортировать музыку и учитывается в результате.
Сначала проверяется наличие выбранных треков и обновляются обложки уже имеющихся,
затем загружаются новые треки. Обложка каждого нового трека появляется сразу вместе
с ним, без ожидания окончания всего импорта. Для VK обложка дополнительно запрашивается
из метаданных `reload_audio`: первичный список может её не содержать.
Для HTTPS-загрузки изображений Rust-коду нужен TLS-модуль GIO (`glib-networking`).
Он включён в Nix-пакет и `nix/shell.nix`; после изменения окружения нужно полностью
выйти из Hopea и запустить её из нового `nix-shell`.
Отсутствующая у сервиса обложка и ошибка её загрузки считаются отдельно.
Spotify импортирует каталог через Spotipy, а аудио — непосредственно из Spotify
через отдельный Rust-процесс `hopea-spotify` на librespot 0.8.0. Нужен Premium
и поддерживаемый аккаунт: некоторые аккаунты не получают ключи аудио после
изменений Spotify. При отказе показывается причина, завершённые файлы остаются.
Подмены аудио записью из YouTube нет. Переключатель загрузки можно выключить,
чтобы импортировать только названия, альбомы и обложки для поиска в P2P.

`hopea/import-history.json` хранит успешные результаты по сервису и ID трека
(существующие установки продолжают использовать прежнее хранилище),
без токенов и ссылок с подписями. Повторный импорт проверяет наличие аудио в узле
и сравнивает содержимое обложки: аудио пропускается, новая обложка обновляет ту же
запись без дубликата. Старые импорты распознаются по `shared-files.json`. Удалённое
аудио и неудачные загрузки можно повторить; завершённые файлы используются из кеша.
Между разными сервисами окончательное устранение дубликатов происходит в узле
по содержимому аудио, поскольку надёжного общего ID у таких записей нет.

После добавления аудио список раздаваемой музыки обновляется автоматически.
Счётчик **Shared** означает добавленные в узел аудиофайлы; **names only** — только
названия для поиска, которым пока нечего раздавать. Нулевая скорость отдачи сама
по себе не означает, что раздача отключена: для передачи нужен запрашивающий пир.

| Сервис | Вход | Что читается | Аудио |
| --- | --- | --- | --- |
| VK | **Sign In with Default Browser…**, затем ID профиля для импорта | Аудиозаписи и все страницы плейлистов | Доступные текущей сессии потоки через `vk-api` |
| Яндекс Музыка | OAuth-токен аккаунта | Лайки, свои и понравившиеся плейлисты, сохранённые альбомы | Доступные аккаунту MP3 через `yandex-music` |
| YouTube Music | **Sign In with Default Browser…** | Библиотека, лайки, плейлисты и альбомы | Доступное аудио через `yt-dlp` |
| Spotify | OAuth access token | Сохранённые песни, плейлисты и альбомы, со всеми страницами | Прямое аудио через librespot, Premium и совместимый аккаунт; также доступен импорт только названий |

Кнопка **Sign In with Default Browser…** открывает сервис в стандартном браузере.
Войдите в обычном, не приватном окне, затем нажмите **Continue** в плеере.
Адаптер через `yt-dlp` читает локальное хранилище cookies браузера и передаёт
приложению только сессию выбранного музыкального сервиса. Поддерживаются Firefox,
Zen, Chrome, Chromium, Brave, Edge, Vivaldi, Opera и Safari, если библиотеке доступен
их профиль и ключ расшифровки. Для Zen читается профиль по умолчанию из
`profiles.ini`, включая свежие изменения cookies ещё открытого браузера.
Если ВК не сохранил `remixmid`, вошедший аккаунт проверяется через страницу ВК;
ID импортируемого профиля не используется вместо ID вошедшего пользователя.
Вход открывается только через стандартный браузер. При нескольких профилях
выберите профиль по умолчанию и войдите в нужный сервис именно в нём.
Если браузер не позволяет прочитать сессию, её можно вставить вручную.
Отдельный Firefox, geckodriver и расширения не нужны.

Если автоматическое чтение сессии не сработало, нажмите **Manual Sign-In
Instructions** под полем сессии. Эта же инструкция доступна из сообщения об
ошибке входа и окна входа в Flatpak. Она относится к выбранному сервису:

- **VK:** откройте `https://vk.ru/audio`, войдите, нажмите F12 → Network
  («Сеть») и обновите страницу. Выберите запрос к `vk.ru`, например `audio`
  или `al_audio.php`. В **Request Headers** скопируйте значение **Cookie**
  целиком, без префикса `Cookie:`. Нужен `remixsid` или `remixsid6`; если есть
  оба, оставьте оба. Сохраните и `remixmid`, если он присутствует. Формат:
  `remixsid=ВАШЕ_ЗНАЧЕНИЕ; remixmid=ID_ВОШЕДШЕГО_АККАУНТА`.
  Не копируйте ответный заголовок `Set-Cookie`. Если `remixmid` отсутствует,
  Hopea сама проверит вошедший аккаунт на VK; ID импортируемого профиля его
  не заменяет. В Zen/Firefox отдельные пары доступны также в Storage → Cookies.
- **YouTube Music:** откройте библиотеку на `music.youtube.com` при открытой
  вкладке Network. Найдите успешный POST-запрос `/browse` и перенесите значения
  `Cookie`, `Authorization`, `X-Goog-AuthUser` в JSON-шаблон из инструкции Hopea.
  Cookie копируется целиком, включая `SAPISID` и `__Secure-3PAPISID`, если они
  присутствуют. Номер аккаунта берите из запроса. Подробности:
  [документация ytmusicapi](https://ytmusicapi.readthedocs.io/en/stable/setup/browser.html).
- **Яндекс Музыка:** нужен OAuth-токен, cookies `Session_id`, `sessionid2`,
  `yandexuid` не подходят. Встроенная инструкция ведёт к
  [руководству библиотеки](https://yandex-music.readthedocs.io/en/main/token.html).
  Вставляйте только токен, без префикса `OAuth`.
- **Spotify:** нужен пользовательский OAuth `access_token` с разрешениями,
  перечисленными в окне импорта. Cookies `sp_dc` и `sp_key`, client secret и
  refresh token в это поле не подходят. Используйте
  [пользовательскую авторизацию Spotify](https://developer.spotify.com/documentation/web-api/tutorials/code-pkce-flow)
  и вставьте токен без `Bearer`.

Данные сессии дают доступ к аккаунту. Вставляйте их только в поле входа Hopea,
не в чат, скриншот или отчёт об ошибке. Примеры в инструкции содержат только
заполнители; реальные значения приложение в инструкцию не подставляет.

Для VK поле **VK Profile ID to Import** — владелец нужной музыки, например
`123456789`. Это может быть другой профиль, чьи аудиозаписи доступны вашему
аккаунту. Вход не заменяет уже введённый ID. Идентификатор вошедшего пользователя
берётся отдельно из сессии. Названия песен сохраняются даже без ссылок на аудио.
При отказе доступа, неожиданном ответе или пустой коллекции появляется отдельное
окно с причиной, а не сообщение об успешном импорте нуля песен.

Для Spotify токен должен иметь права `user-library-read`,
`playlist-read-private`, `playlist-read-collaborative`, а для аудио ещё `streaming`.
Это **пользовательский**
access token, а не client secret или токен Client Credentials. Получение
описано в [Spotify OAuth](https://developer.spotify.com/documentation/web-api/tutorials/code-pkce-flow).
Способы получения токена Яндекса описаны в
[документации yandex-music](https://ym.marshal.dev/).
Ни один токен не нужно отправлять в чат.

Если сессия стандартного браузера недоступна, для VK можно вручную вставить заголовок `Cookie`
запроса собственной сессии и свой числовой ID. Для YouTube Music принимается
JSON заголовков в формате
[ytmusicapi browser authentication](https://ytmusicapi.readthedocs.io/en/stable/setup/browser.html).
В этом случае расширение тоже не требуется.

Данные авторизации передаются адаптеру через stdin, не через аргументы
командной строки. Они не записываются в настройки или отчёты приложения;
ответы с cookies и подписанными URL не выводятся в журнал.

## Зависимости и запуск

Сам плеер, интерфейс импорта и открытие стандартного браузера написаны на Rust.
`hopea-spotify` тоже написан на Rust и устанавливается Meson рядом с плеером.
Собирайте плеер и этот пакет отдельными командами: `cargo build --workspace`
объединяет несовместимые clock-features зависимостей librespot и P2P-узла.
Обычный `meson compile -C _builddir` уже выполняет обе нужные команды.
`src/library/service_import.py` — отдельный адаптер к библиотекам сервисов
и `yt-dlp`, без собственного веб-сервера или фонового демона.

В каталоге проекта один раз создать окружение:

```sh
nix-shell -p python3 python3Packages.virtualenv --run \
  'python3 -m virtualenv .venv-import && .venv-import/bin/python -m pip install --upgrade pip==26.3 && .venv-import/bin/python -m pip install -r build-aux/import-requirements.txt'
```

`nix/shell.nix` предоставляет FFmpeg, а также подставляет
интерпретатор `.venv-import/bin/python`, если окружение существует.
Сборка и запуск остаются через Meson:

```sh
nix-shell nix/shell.nix --run 'meson compile -C _builddir'
nix-shell nix/shell.nix --run 'meson devenv -C _builddir ./src/hopea'
```

На другой системе установить зависимости из того же requirements-файла в
отдельное Python-окружение и FFmpeg. Перед запуском
задать `HOPEA_IMPORT_PYTHON=/полный/путь/к/окружению/bin/python`.
Если переменная не задана, приложение ищет `python3` в `PATH`.
Старые Flatpak/Nix-архивы этой возможности не содержат; они не пересобирались.

## Обработка результата

- Чтение идёт со всех страниц, дубли внутри импорта отбрасываются по ID сервиса.
- Доступные файлы приводятся FFmpeg к FLAC с названием и исполнителем в тегах.
  Это не улучшает качество исходной записи; FLAC выбран как поддерживаемый
  контейнер без дополнительного сжатия с потерями. Файлы могут быть крупнее исходных.
- Перед добавлением и раздачей каждый файл проходит обычную проверку узла.
  Ограничения размера, форматов и названия продолжают действовать.
- Завершённые загрузки лежат в пользовательском каталоге
  `hopea/imports/<service>/`. Повторный запуск использует их вместо повторного
  скачивания. Отмена сохраняет уже прочитанные названия и готовые файлы.
- Песни без доступного аудио сохраняются в `wanted.json` для поиска в сети.
  Ошибка авторизации или изменения сайта не выдаются за успешный полный импорт.
- За один запуск обрабатывается до 20 000 уникальных песен. При превышении
  выводится сообщение о неполном импорте. Для YouTube запросы отдельных разделов
  также ограничены этим числом.

Проверки без аккаунтов:

```sh
nix-shell nix/shell.nix --run 'meson test -C _builddir --suite import --print-errorlogs'
```

Библиотеки VK, Яндекса и YouTube используют неофициальные интерфейсы сервисов.
Их работоспособность зависит от изменений сайта, региона, сессии и прав аккаунта.
Автоматические проверки покрывают ответы сервисов и протокол рабочего процесса;
они не заменяют проверку на реальном аккаунте.

## Происхождение и проверка зависимостей

Используются исходные проекты: [vk-api](https://github.com/python273/vk_api),
[yandex-music](https://github.com/MarshalX/yandex-music-api),
[ytmusicapi](https://github.com/sigma67/ytmusicapi),
[Spotipy](https://github.com/spotipy-dev/spotipy),
[yt-dlp](https://github.com/yt-dlp/yt-dlp),
[Beautiful Soup](https://www.crummy.com/software/BeautifulSoup/bs4/),
[PyCryptodome](https://github.com/Legrandin/pycryptodome) и
[SecretStorage](https://github.com/mitya57/secretstorage).
Сторонние адаптеры не являются официальными SDK музыкальных сервисов.

Для прямого аудио Spotify используется опубликованный релиз
[librespot 0.8.0](https://github.com/librespot-org/librespot/releases/tag/v0.8.0),
только компоненты core/audio/metadata. Версии закреплены в `spotify/Cargo.toml`
и общем `Cargo.lock`; совместимая версия build-зависимости `vergen` — 9.0.6.
Connect, обнаружение устройств и сохранение учётных данных не включены.
Рабочий процесс не инициализирует журнал: trace-логи самой библиотеки способны
содержать токены. FFmpeg получает только временный аудиофайл и теги, без токена;
сетевые протоколы FFmpeg отключены. Действуют ограничения размера и времени,
сравнение длительности и проверка аудио узлом перед раздачей. Полученный Vorbis
конвертируется в FLAC для общего пути импорта; это не повышает качество источника.

Проверка `cargo-audit 0.22.1` от 12 ноября 2026 года выявила у первоначальной
Rustls-конфигурации старые TLS-зависимости. Вместо неё выбран `native-tls`
с системным TLS и обычной проверкой сертификатов. Старые rustls 0.22 и
rustls-webpki 0.102 исключены. Проверка общего lockfile всё ещё сообщает:

- `RUSTSEC-2026-0194/0195`, quick-xml 0.38.4: librespot использует обычный
  `Reader` и не перебирает атрибуты; уязвимые `NsReader` и проверка повторных
  атрибутов в проверенном пути ProductInfo не вызываются.
- `RUSTSEC-2023-0071`, rsa 0.9.10: librespot проверяет подпись сервера открытым
  ключом; уязвимая операция с приватным ключом в этом пути не используется.
- `RUSTSEC-2026-0293`, ringbuf 0.4.8: существующая зависимость P2P-узла, которая
  не входит в отдельный Spotify-процесс; это предупреждение не исправлено здесь.

Это анализ применимости известных предупреждений, а не чистый результат аудита
и не гарантия отсутствия других проблем. Предупреждения не внесены в ignore-list.
При обновлении librespot нужно повторить аудит и проверку вызовов. Для повторения:
`cargo audit --json`; тесты рабочего процесса: `cargo test -p hopea-spotify
--target-dir _builddir/src -- --include-ignored` внутри `nix-shell`.

На 12 ноября 2026 года `pip-audit 2.10.1` проверил 22 установленных пакета
окружения импорта по базе PyPI. Старый `pip 25.3` имел известные уязвимости;
после обновления до `26.3` повторная проверка не нашла известных уязвимостей
и не пропустила ни одного пакета. Это проверка опубликованных уязвимостей,
а не полный аудит исходного кода или гарантия безопасности.
Прямые версии закреплены в `build-aux/import-requirements.txt`, транзитивные —
в `build-aux/import-constraints.txt`; при обновлении нужны повторные проверки.

Пароли вводятся на сайте в браузере. Приложение не сохраняет cookies для
следующих входов, в настройки или журнал; cookies других сайтов не передаются плееру.
При чтении обычного профиля yt-dlp создаёт временную копию базы cookies и удаляет
её по завершении чтения; при аварийном завершении процесса копия может остаться.
Автозагрузка сторонних плагинов yt-dlp отключена. Адаптер работает отдельным
процессом, но это не системная песочница: он имеет права запустившего его пользователя.

Регрессионный GTK-тест `window::tests::navigation_preserves_playback_and_settings_open_without_search`
проверяет сохранение очереди, песни и позиции при смене вкладок, а также настройки
при скрытом поиске. Его запускают через `cargo test --target-dir _builddir/src
navigation_preserves -- --ignored --test-threads=1` в `nix-shell`, после Meson-сборки,
с тестовым дисплеем GTK, `GSETTINGS_BACKEND=memory`, `GSETTINGS_SCHEMA_DIR` указывающим
на `_builddir/data` и временными каталогами `XDG_DATA_HOME`, `XDG_CONFIG_HOME`,
`XDG_CACHE_HOME` внутри `/tmp`.
Он также проверяет доступность Import для разных полей и сервисов. Для проверки
ошибки запуска без обращения к сервисам задать
`HOPEA_IMPORT_PYTHON=/nonexistent/hopea-test-python` только на время теста.

Для явной проверки на собственном аккаунте есть отдельный выключенный по
умолчанию тест `live_zen_music_import`. В обычном окружении пользователя,
с открытым входом в Zen и временным `HOPEA_LIVE_IMPORT_DIR` внутри `/tmp`,
он читает каталог и импортирует один трек с обложкой. Cookies передаются только
через stdin; тест не публикует трек и не изменяет основную библиотеку.
Полученные `selected.flac` и `selected.cover.jpg` можно проверить в изолированном
GTK-тесте, передав ему тот же `HOPEA_LIVE_IMPORT_DIR`;
`HOPEA_TEST_REAL_COVER_SCREENSHOT` задаёт путь снимка окна с этой обложкой.

## Свои альбомы

**My Albums** находится над очередью треков (и в главном меню).
**New Album** открывает редактор: обязательное имя, обложка PNG/JPEG,
**Add Songs** с выбором треков из My Music, перемещение вверх/вниз и удаление
из состава. **Save** сохраняет коллекцию между запусками. Исходные теги
аудиофайлов не меняются. **Play Album** ставит выбранные песни в начало
My Music в порядке альбома; остальные песни остаются в очереди.

**Share Album…** раздаёт локальные песни через встроенный узел; для сетевых
песен включает сохранение и ждёт проверенную полную копию. Затем сохраняет
`.hopea-album.json` с именем, обложкой и упорядоченными хешами файлов.
Этот файл можно передать другому пользователю Hopea; кнопка открытия в
**My Albums** читает его и находит аудио по точному хешу через Shared Music.
Локальные пути, cookies и токены в общий файл не входят. Это обмен файлом
коллекции; отдельного глобального каталога пользовательских альбомов пока нет.

## Прогресс и кэш

Import Progress показывает этап, трек, выполненное количество и приблизительное
оставшееся время по средней длительности уже обработанных треков. Оценка
появляется после первых двух треков и уточняется во время работы; при медленном
ответе сервиса она может увеличиваться. Ошибки выделены красным отдельно от
обычных счётчиков, завершение — зелёным при отсутствии ошибок скачивания.

В **Settings → Storage → Clear Cache…** можно отдельно выбрать кэш обложек,
форм волн и загруженных текстов песен. Перед очисткой показываются размеры;
после — реально освобождённое место. Музыка, файлы альбомов, история импорта,
исходные обложки и восстановление очереди не удаляются. Активная обложка
плеера сохраняется, остальные кэшированные изображения могут создаваться снова.

Чтение коллекций VK использует структурированный `owner_playlists` с пагинацией
по 50 записей вместо устаревшей мобильной HTML-разметки. Недоступная коллекция
не скрывает остальные. Проверка с разрешённой сессией Zen прочитала 61 запись
коллекций; для 59 удалось получить состав и обложку, итог — 3 128 уникальных
треков. Две нечитаемые коллекции отображаются предупреждением. Эта проверка
читала каталог, не скачивала аудио.

### Выбор альбомов и сравнение версий

Альбомы и плейлисты выбираются целиком. Если в коллекции найдены возможные
дубликаты, она изначально снята с выбора целиком; выбрать её можно общей галочкой.
Поиск и «скрыть дубликаты» меняют видимый список, но не состав выбранного альбома.
Трек, входящий в несколько выбранных коллекций, скачивается один раз.

В сравнении показаны имеющаяся и входящая версии с отдельным прослушиванием.
**Keep Left** использует имеющийся трек, **Download Right** заменяет запись в
медиатеке после успешной загрузки, **Keep Both** оставляет обе разные версии.
Точные совпадения по хешу не создают вторую копию аудио. Кнопка **Back to Songs**
возвращает к прежнему списку, сохраняя решения.

При замене старый аудиофайл сохраняется в `replaced-audio` в каталоге данных
Hopea. Перед удалением старой записи проверяются размер и SHA-256 сохранённого
файла. Если загрузка или сохранение не удались, старая запись остаётся.
Оригинальный файл пользователя и настройки корзины не затрагиваются.


### Избранное, альбомы и прослушивание

Личный плейлист содержит избранные песни. Нажатие на результат поиска запускает
предпрослушивание; звёздочка сохраняет песню в плейлист. Одиночное прослушивание
заканчивается после песни, а внутри альбома продолжается следующей песней этого
альбома. Избранное при этом не меняется.

«Мои альбомы» и содержимое найденного альбома открываются на месте левого списка.
Кнопка «Назад» возвращает предыдущую страницу; вкладка My Music возвращает плейлист.
Редактирование альбома вызывается отдельно кнопкой Edit Album.

Выбранные при импорте коллекции сохраняются в «Моих альбомах» с исходным порядком
песен. Повторный импорт обновляет ту же коллекцию. Если импорт прерван, песни без
загруженного аудио остаются обозначенными как недоступные. Исключённые сервисом
альбомы перечислены в Details предупреждения; незавершённые списки не выдаются за
полные альбомы.

Вся музыка, добавленная в Hopea и доступная локально, раздаётся при включённой
раздаче с учётом настройки VPN. Снятие звёздочки не перемещает и не удаляет файл.
Произвольные папки компьютера автоматически не сканируются. Поиск новой музыки
скрывает локальные записи и известные совпадения аудиохеша; проверка окончательного
хеша после загрузки продолжает работать.


При пустом запросе поиск показывает приглашение найти музыку, альбомы и
исполнителей. Старые записи каталога не выводятся автоматически. Новый запрос
перепроверяет источники; открытые результаты проверяются примерно каждые 30 секунд.
Песня исчезает, если доступных источников больше нет, и остаётся, если хотя бы
одна подтверждённая копия доступна. Метаданные при этом не удаляются.

Если файл кешированной обложки пропал, узел сбрасывает устаревшую отметку кеша и
повторно получает изображение, проверяя его подписанный хеш. Недоступная обложка
возвращает 404, а не внутреннюю ошибку ENOENT. Аудиофайлы этим исправлением не меняются.
